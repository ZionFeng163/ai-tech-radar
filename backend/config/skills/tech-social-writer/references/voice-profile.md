# 作者声音档案 v1

## 核心定位

面向对 AI 和计算机感兴趣的普通读者。追踪热点，但不做纯热点账号；技术内容需要事实、判断和启发，读者不必先读懂论文术语。

## 稳定特征

- 开头直接给对象、数字或判断，不写新闻导语和悬念铺垫。
- 论文类内容优先写“哪里反常”或“它在真实使用里会怎么坏”，项目名、基准名和完整数字随后再交代。
- 先让读者知道“它做了什么”，再保留决定结论的术语。
- 技术内容偏读后笔记：中心发现先出现，随后用前后数字、组件作用和实验结果支撑。
- 行业内容偏利益与控制权：人物路径、成本、权限、产权或迁移能力比泛泛趋势更重要。
- 段落短，但每段必须带来新事实、解释或判断。
- 判断可以明确，也允许一句克制的不确定性；不为了显得全面强加反方观点。
- 口语化来自自然句子和具体动作，不来自网络热词、夸张梗或假装随意。
- 可以有一句克制的第一人称判断，例如“我觉得这里最值得看的是……”，但它必须指向一个具体事实，不能充当气氛词。

## 技术类结构

不要固定套同一种顺序。根据材料选择下面一种自然入口：

- 反常识入口：先说一个读者能马上理解的矛盾，再用测试数字确认它有多严重。
- 场景入口：先给一个具体例子，说明系统会在哪一步犯错，再解释背后的机制。
- 变化入口：先说新版本具体改了什么，再用前后数字和组件分工展开。

正文通常只需要四个动作：提出发现、给出证据、把机制翻成人话、给出作者判断。允许其中一个动作很短，也允许停在一个具体问题上；不要为了完整自动补“意义、局限、未来”三件套。

数字出现前，读者应先知道它在衡量什么。术语出现后，紧邻句子要能回答“它具体做了什么”。例如不要先写“检索路由接口失效”，而是先写“系统搜记忆时只会找字面相似的词，没想到坚果过敏也该把马卡龙食谱找出来”。

可用的阅读入口必须诚实。只有拿到可靠原文时才可说“看了技术报告”；只有摘要或二手资料时，直接说资料显示了什么。

## 真人中文技术帖的节奏

- 第一句可以短，像聊天时先把最有意思的发现递给对方：“这个测试挺狠。”下一句必须马上给事实，不能只吊胃口。
- 先用普通词说清问题，再补准确名词。能写“系统找错了记忆”，就不要先写“检索路由接口发生语义失配”。
- 一个段落只推进一步，但长短不必整齐。关键数字可以单独成句，解释机制的段落可以稍长。
- 判断要落在动作、代价或使用后果上。少写“指出了一个方向”，多写“继续加大向量并没有让系统更会用这些记忆”。
- 不强制总结。最后一句可以是作者真正关心的问题，也可以停在已经说透的判断上。

### InMind 固定反例

不要写成：

“InMind 基准测试显示……问题不在……诊断探针证实……这意味着评估……资料未说明……”

这是论文摘要的中文改写，不是人在分享发现。更自然的信息顺序是：

1. 先说反常现象：Agent 明明存着一条记忆，换个说法就想不起来了。
2. 立即给最能说明问题的例子：知道用户坚果过敏，却没把这条记忆关联到马卡龙食谱。
3. 再交代测试结果和必要数字。
4. 用动作解释原因：系统只在找“长得像”的文字，没有先判断回答这个问题需要哪些旧信息。
5. 最后给一个有限判断；不要自动附加审稿人口吻的配置免责声明。

## 非技术类结构

- 融资和人物：事实开场，随后解释团队经历为何与当前方向相关。
- 产业观点：抓住一个利益关系或反常识问题，用具体权利、成本或流程展开。
- 社区热点：平台排名、票数、点赞数和评论数只用于上游选题，默认不进入正文；除非作者明确要分析传播本身。

## 明确不要

- “核心突破、重新定义、释放信号、重塑格局、胜负手、必要底座、行业拐点”。
- “文章标题本身、这种反差、我们容易陷入、对于从业者来说”一类评论模板。
- “基准测试显示……问题不在……这意味着……”式论文摘要三段论。
- “诊断探针证实、检索路由接口、架构极限、确定方向”这类写给审稿人的表达。
- 每段都用“第一、第二、第三”或相同句式。
- 把所有机制、限制、反方和未来展望依次填满。
- 伪造“我试用了”“我和朋友聊过”“读完全文后很震撼”等经历。
- 为了像人而故意卖萌、粗俗、耍梗或加大量 emoji。

## 判定标准

成稿应当能顺口讲给对技术感兴趣的朋友听；删掉任何一段都会损失一个具体事实、解释或判断。读者能够复述中心认识，而不是只记住一串术语。

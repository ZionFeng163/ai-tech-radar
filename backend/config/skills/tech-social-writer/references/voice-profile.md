# 作者声音档案 v1

## 核心定位

面向对 AI 和计算机感兴趣的普通读者。追踪热点，但不做纯热点账号；技术内容需要事实、判断和启发，读者不必先读懂论文术语。

## 稳定特征

- 开头直接给对象、数字或判断，不写新闻导语和悬念铺垫。
- 先让读者知道“它做了什么”，再保留决定结论的术语。
- 技术内容偏读后笔记：中心发现先出现，随后用前后数字、组件作用和实验结果支撑。
- 行业内容偏利益与控制权：人物路径、成本、权限、产权或迁移能力比泛泛趋势更重要。
- 段落短，但每段必须带来新事实、解释或判断。
- 判断可以明确，也允许一句克制的不确定性；不为了显得全面强加反方观点。
- 口语化来自自然句子和具体动作，不来自网络热词、夸张梗或假装随意。

## 技术类结构

1. 用一句话给出可验证发现。
2. 用成对数字说明相对上一代或基线发生了什么。
3. 只解释支撑判断的组件，并说明每个组件负责什么。
4. 用资料里的实验结果或真实边界收住。

可用的阅读入口必须诚实。只有拿到可靠原文时才可说“看了技术报告”；只有摘要或二手资料时，直接说资料显示了什么。

## 非技术类结构

- 融资和人物：事实开场，随后解释团队经历为何与当前方向相关。
- 产业观点：抓住一个利益关系或反常识问题，用具体权利、成本或流程展开。
- 社区热点：热度数字只证明讨论多，不证明社区认同、焦虑或形成共识。

## 明确不要

- “核心突破、重新定义、释放信号、重塑格局、胜负手、必要底座、行业拐点”。
- “文章标题本身、这种反差、我们容易陷入、对于从业者来说”一类评论模板。
- 每段都用“第一、第二、第三”或相同句式。
- 把所有机制、限制、反方和未来展望依次填满。
- 伪造“我试用了”“我和朋友聊过”“读完全文后很震撼”等经历。
- 为了像人而故意卖萌、粗俗、耍梗或加大量 emoji。

## 判定标准

成稿应当能顺口讲给对技术感兴趣的朋友听；删掉任何一段都会损失一个具体事实、解释或判断。读者能够复述中心认识，而不是只记住一串术语。

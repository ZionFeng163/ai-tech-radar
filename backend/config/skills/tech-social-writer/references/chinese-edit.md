# 中文成稿修补

只在事实和中心判断稳定后处理文字。默认做最小修改，不重写已经自然的段落。

## 不可破坏

- 不新增事实、案例、人物、数据或结论。
- 不虚构第一人称经历、情绪、对话和使用体验。
- 不删除决定结论边界的条件。
- 不把作者明确的判断磨成中性说明书。
- 不为压缩篇幅删掉数字所属的项目、测试范围或对照基线。

## 优先检查

1. 每段是否增加了新信息；只有换词重复时删除。
2. 是否先宣布“重要、反常识、真正关键”，却没有让事实自己说明。
3. 是否连续使用相同段落长度、三段式或“观点句 + 解释 + 总结”。
4. 是否出现机械二分：“不是 A，而是 B”“不只 A，更是 B”。
5. 是否用反问拖延答案：“这意味着什么”“为什么值得关注”。
6. 是否用报告路标组织正文：“首先、其次、值得注意、总的来说”。
7. 是否堆叠抽象词：“格局、趋势、范式、底座、重构、赋能、信号”。
8. 是否每个必要术语都能从紧邻句子理解其动作和作用。
9. 数字结论是否仍能回答“谁、在什么测试里、相对什么”；不能时补回必要上下文。
10. 是否把论文标题、基准名或完整数字塞在第一句，读者还不知道它为什么有意思。
11. 是否形成“研究显示 → 问题不在 → 这意味着 → 资料未说明”的论文摘要骨架。
12. 例子是否要求中文读者先懂某种外国食物、节日、校园或职场文化，才能理解技术关系。

## 修法

- 直接说事实，删除宣布意义的前缀。
- 用具体名词、动作、数字替换抽象判断。
- 改变信息进入方式，而不是机械替换段首词。
- 保留自然的不规则节奏；不要为了“像人”故意加入口头禅。
- 允许段落停在事实、限制或尚未解决的问题上，不补万能总结。
- 遇到论文摘要式开场，先找材料里最具体的失败场景、反常结果或前后变化，把它移到最前面。
- 把“检索路由、诊断探针、语义激活”之类名词改写成系统正在执行的动作；技术名只在保留它能帮助读者时出现一次。
- 不要机械删除所有边界说明。只保留会改变读者判断的限制，并放在相关结论旁边，不单独写审稿人免责声明。
- 陌生文化对象不是文章主题时，把它改成能保留同一事实关系的自然说法；例如把具体西式食物和原料关系收成“用户有忌口，推荐吃什么时却没用上这条信息”。不要为了本地化虚构新的案例，也不要写成“含某原料的食物”这种分类说明。
- 把句子念一遍：如果日常聊天会说“吃不了、忌口、推荐吃什么”，就不要写“某类原料、某类物质、食物推荐场景”。

最终只返回成稿或结构化审校意见，不向读者展示写作过程。
